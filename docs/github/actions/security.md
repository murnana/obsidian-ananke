# セキュリティ対策

このプロジェクトの GitHub Actions で実施しているセキュリティ対策について説明します。

## なぜセキュリティ対策が必要なのか

GitHub Actions のワークフローは、リポジトリのコードにアクセスし、外部のアクション（他のリポジトリのコード）を実行します。もし悪意のあるコードが混入すると、以下のようなリスクがあります:

- リポジトリのシークレット（トークンやAPIキーなど）の漏洩
- リポジトリへの不正な変更
- サプライチェーン攻撃（依存先を通じた間接的な攻撃）

## 対策 1: SHA ピン留め（SHA Pinning）

### 問題

アクションをタグで指定する場合（例: `uses: actions/checkout@v6`）、タグはリポジトリのオーナーがいつでも上書きできます。もしアクションのリポジトリが侵害されると、同じタグ名のまま悪意のあるコードに差し替えられる可能性があります。

### 対策

タグの代わりに、コミットの SHA ハッシュ（40 文字の一意な識別子）でアクションを指定します。SHA はコミットの内容から計算されるため、内容が変わると SHA も変わります。これにより、知らないうちにコードが差し替えられることを防げます。

```yaml
# 危険: タグはいつでも上書き可能
- uses: actions/checkout@v6

# 安全: SHA はコミットに固定されるため改ざん不可能
- uses: actions/checkout@de0fac2e4500dabe0009e67214ff5f5447ce83dd # v6
```

末尾のコメント（`# v6`）は、どのバージョンに対応する SHA なのかを人間が把握するためのものです。動作には影響しません。

### SHA の調べ方

特定のタグに対応する SHA は、以下のコマンドで確認できます:

```bash
# GitHub CLI を使う方法
gh api repos/{owner}/{repo}/git/ref/tags/{tag} --jq '.object.sha'

# 例: actions/checkout の v6 タグ
gh api repos/actions/checkout/git/ref/tags/v6 --jq '.object.sha'
```

## 対策 2: 最小権限の原則

### 問題

GitHub Actions のワークフローには、デフォルトでリポジトリに対する広い権限が付与されます。これは、アクションが侵害された場合の影響範囲を大きくします。

### 対策

ワークフローレベルですべての権限を無効化し、各ジョブに必要最小限の権限だけを付与します。

```yaml
# ワークフローレベル: すべての権限を無効化
permissions: {}

jobs:
  my-job:
    # ジョブレベル: 必要な権限のみ付与
    permissions:
      contents: read  # リポジトリの内容を読み取るだけ
```

### 主な権限一覧

| 権限 | 説明 | `read` | `write` |
| --- | --- | --- | --- |
| `contents` | リポジトリのコード | コードの読み取り | コードの変更・コミット |
| `pull-requests` | プルリクエスト | PR の閲覧 | PR の作成・コメント |
| `issues` | イシュー | イシューの閲覧 | イシューの作成・編集 |
| `packages` | GitHub Packages | パッケージの取得 | パッケージの公開 |

## 対策 3: 同時実行制御

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

同じブランチへの連続プッシュで古い実行をキャンセルします。これはセキュリティというよりリソース効率の対策ですが、不要な実行を減らすことで攻撃対象面（attack surface）も小さくなります。

## 対策 4: Dependabot による自動更新

アクションやパッケージの脆弱性は、定期的にアップデートすることで修正されます。Dependabot が毎週、依存関係のアップデートを確認し、プルリクエストを自動作成します。

## アクション追加時のチェックリスト

新しいアクションをワークフローに追加する際は、以下を確認してください:

1. **SHA ピン留め** — タグではなく SHA でアクションを指定する
2. **末尾コメント** — SHA の後にバージョンのコメント（`# v6` など）を付ける
3. **権限の確認** — ジョブに必要最小限の権限のみを付与する
4. **アクションの信頼性** — 公式アクション（`actions/` や `github/`）またはよく知られたアクションを優先する
5. **Dependabot 設定** — `github-actions` のエコシステムが設定されていることを確認する
