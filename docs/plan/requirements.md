# Ananke 要件定義書

## 1. 背景と経緯

Ananke は当初、TaskChute 方式(1日をタイムラインとして扱い、タスクの見積もり・時間記録・振り返りを回す)を Obsidian 上で実現するプラグインとして設計された。旧設計(4フェーズ計画)のうち Phase 1(デイリープランビュー)まで実装した時点で開発が停止し、以降は依存関係の更新のみが続いていた。Phase 1 の成果物は日常のワークフローに組み込まれることがなかった。

2026-07 に現状整理と要件の再ヒアリングを行った結果、本当に解決したかった課題は「時間の記録」ではなく **「タスクの抜け漏れ・忘却の防止」** であることが判明した。旧設計の中核だったタイマー・タイムログ・見積もり精度分析・ルーチン自動展開は、この課題に対して過剰装備であり、着手の重さが開発停止の一因にもなっていた。

本書は、ヒアリング結果に基づいて Ananke の要件をゼロから定義し直したものである。旧設計ドキュメント(overview / data-model / features / phases)は本書に置き換えられ、削除された(git 履歴からは参照可能)。

## 2. コンセプト

> 思いついたタスクを最速で Inbox に放り込み、あとでプロジェクトへ振り分け、プロジェクト単位で俯瞰する。タスクはメモと同じ Vault に、1タスク = 1ノートとして同居する。

Ananke は murnana 個人のためのタスク管理プラグインである。汎用性・公開よりも「自分が毎日使い続けられること」を最優先する。

## 3. 解決したい課題

**やるべきことの抜け漏れ・忘却。**

タスクは次の3つの発生源から生まれるが、発生した瞬間に確実に捕捉する仕組みがないため、思い出せなくなる・拾い忘れる:

1. **仕事の依頼・会議** — 会議中・チャット・口頭で発生するタスク
2. **開発・制作作業** — 自分のプロジェクトの作業分解から生まれるタスク(このプラグインの開発自体を含む)
3. **Obsidian のノート内** — メモやデイリーノートに書き散らしたチェックボックス・TODO

## 4. ユースケース

### UC-1: 即時キャプチャ

作業中・会議中にタスクを思いついたら、コマンド(ホットキー)またはリボンアイコンからタイトルを入力するだけで、タスクノートが Inbox に作成される。文脈を離れず数秒で完了すること。

### UC-2: Inbox の振り分け

時間のあるときに Inbox ビューを開き、未整理のタスクを順にプロジェクトへ振り分ける(または不要なら削除する)。

### UC-3: プロジェクト俯瞰と着手

プロジェクトビューでプロジェクト毎のタスク一覧を眺め、状態(未着手 / 進行中 / 完了)を把握・更新しながら作業を進める。

### UC-4: タスクノートへのメモ追記

タスクの詳細・経緯・調べたことは、そのタスクノートの本文に通常の Obsidian ノートとして自由に書く。他のノートへのリンク・埋め込みも通常どおり使える。

## 5. データモデル

### 1タスク = 1ノート

タスクは `taskFolder`(設定項目、既定: `ananke-tasks`)配下の個別 Markdown ファイルとする。

```
ananke-tasks/
├── リリースノートを書く.md
├── 会議資料の修正依頼.md
└── ...
```

タスクの属性は frontmatter に持ち、本文は自由なメモ欄とする:

```markdown
---
ananke-type: task
status: inbox        # inbox | todo | doing | done
project:             # 未設定 = Inbox。設定されたらそのプロジェクトに所属
created: 2026-07-07T10:30
---

ここから下は自由記述。経緯・参考リンク・作業メモなど。
```

- **Inbox** = `project` が未設定のタスクノートの集合(状態 `inbox`)
- **プロジェクト** = frontmatter の `project` 値によるグルーピング。まずは文字列で始め、将来的にプロジェクトノートへのリンク(`[[...]]`)化を検討する
- `ananke-type` フィールドは旧設計から引き継ぎ、将来のデータ形式変更に備える

### 設計原則(旧設計から引き継ぐもの)

- **プレーンテキスト透明性**: プラグインなしでも人間が読める・編集できる。frontmatter は Obsidian 標準のプロパティ UI でも編集可能
- **非破壊**: 既存の Vault 構造に干渉しない。プラグインが書き込むのは `taskFolder` 配下のみ(将来のチェックボックス昇格機能を除く。その場合も明示的な操作時のみ)
- **Obsidian First**: frontmatter の読み書きは `metadataCache` / `FileManager.processFrontMatter` を使い、自前パーサを持たない

## 6. 機能要件

### MVP(これだけで毎日使い始める)

| # | 機能 | 内容 |
|---|---|---|
| F-1 | クイックキャプチャ | コマンド + リボンアイコンからモーダルを開き、タイトル入力のみでタスクノートを Inbox に作成する |
| F-2 | Inbox ビュー | `project` 未設定のタスク一覧を表示し、プロジェクトへの振り分け・削除ができる |
| F-3 | プロジェクトビュー | プロジェクト毎にタスクを一覧表示し、状態(todo / doing / done)を変更できる |
| F-4 | タスクノートを開く | 一覧の任意のタスクからノート本体をワンクリックで開ける |

### 将来(MVP 定着後に検討)

- ノート内チェックボックスの「タスクノート昇格」コマンド(発生源3への対応)
- 期日(due)と期日ベースの並び替え・強調
- 完了タスクのアーカイブ(一覧から隠す / フォルダ移動)
- 週次見直し用の一覧(溜まった doing・古い inbox の検出)

### スコープ外(旧設計から削除)

以下は現在の要件に含まれない。必要になった時点で改めて要件化する:

- タイマー・経過時間表示
- タイムログ(CSV)・実績時間の記録
- 見積もり精度の分析・統計
- ルーチンの自動展開・繰り返し条件
- デイリープラン(日付単位の実行計画)ビュー

## 7. 非機能要件・制約

- **自分専用**: コミュニティプラグインとしての公開・汎用化・新規言語追加は当面行わない。既存の i18n 基盤(i18next + `assets/i18n/ja.json`)はそのまま流用する
- **デスクトップ優先**: モバイル対応は必須としない
- **Obsidian API 準拠**: `Vault` / `MetadataCache` / `ItemView` / `Modal` 等の公式 API を用い、プラットフォーム制約を尊重する
- **既存ビルド・CI 基盤の維持**: esbuild + Lightning CSS、GitHub Actions(リリース・セキュリティ・テスト)、自作テストランナーは現状のまま流用する
